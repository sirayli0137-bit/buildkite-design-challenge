Slide 15b — What I'd do differently

Six things I'd do with more time

Not vague wishes. Each is a concrete piece of work I'd plan. Three big-picture (left) and three tactical improvements that surfaced in the metrics review (right).

Big-picture
01

Watch real Buildkite developers use it

I haven't seen a real user touch this yet. One observation session is worth three rounds of polish.

02

Plug in a real AI service

The pattern table stands in for a real AI. With one, I'd tune confidence on real signals and use the new feedback loop to improve over time.

03

Build the full cross-build view

The banner is now actionable. The full view — affected builds, root cause, escalation — is a separate component I'd design next.

Tactical (deferred from metrics review)
04

Rank multi-failure rows by blast radius (V7.4)

Today five rows are visually equal. Sort by downstream impact so the most-blocking failure leads. Add a small "blocks N steps" tag.

05

Surface "waiting on" for stuck steps (V7.1)

"Stuck" doesn't say why. Show what it's waiting on ("runner pool, ~45s") so users don't leave the page to investigate.

06

Handle long pipelines

Demo has 6 steps. Real Buildkite pipelines have 15–30. Find the threshold where the strip wraps badly and switch to the bar version automatically.
