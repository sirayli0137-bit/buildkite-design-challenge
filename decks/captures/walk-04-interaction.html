Slide 4 — Interaction design

Stronger button = bigger action

How a button looks tells you how big the action is — before you read the label.

Buttons in order of commitment

Text link Just look
Plain button No risk
Outlined button Reversible
Outlined, expandable Look first, then act
Filled button Real change
Why → Apply fix is the only filled button on screen, because it's the only one that actually changes code. You can read commitment off the button before reading the label.

Every state change is shown, not assumed

Preview fix → Apply fix → Fix applied. Three steps, each with its own visual.

Preview fix ▾ → Diff visible · Apply fix
Click Apply → ✓ Fix applied · Pipeline re-running

The expand button sits right next to what it expands

No diagonal eye-track. The chevron rotates ▾ → ▴ to confirm the toggle.

Why → Hidden state changes break trust. When you click Apply, you immediately see a green row that names the file changed, with a way to undo.
